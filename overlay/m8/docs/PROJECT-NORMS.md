# AirSIM M8 · 自建项目规范

适用范围：本仓库（`shangjie1998/airsim-m8-openwrt`，VIPME-M8 一线）。只管 M8，不涉及 F50；安装包与文档不与另一机型互换。

## 一、流程

1. 每一阶段动手前先给清单：改什么、改哪些文件、风险在哪、验完怎么判。用户确认后才动。
2. **提交、推送、发 Release 之前必须先经用户确认**（清单要落到文件级：文件、增删行数、目标版本）。
3. 上游功能优先、作者优先。确实跑不动才做最小绕行，并逐条记录原因（写进 `docs/` 或版本说明）。
4. 功能加入与个性化改动都要二次确认；个性化需求先问清效果再给方案。
5. 出现取舍冲突时两版都留，用户实测选留：好用那版进 `overlay/m8/`，另一版进 `saves/<日期>-<主题>/`。
6. 请求不明确、或与现有实现不一致时，双方确认后再实施。

## 二、仓库结构

```
src/            上游 v0.1.0-r22 原版，一字不改
overlay/m8/     全部自建改动（同名相对路径覆盖 src）
upstream/r22/   上游原件存档副本，配 tag upstream-r22
scripts/        build.sh（src+overlay 合成）、bump-version.sh
README-M8.md    入口文档（留在根）
docs/           本规范等自建文档（在 overlay/m8/docs/）
```

7. `src/` 只放上游原版，禁止在里面改任何字符。
8. `overlay/m8/` 放全部自建改动：文案、参数、内核适配、LuCI 资产、打包骨架 `m8-pkg/`。一小份一小份文件，禁止再造平行拷贝（历史上 `packaging/openwrt/root/` 与 `m8-pkg/` 各一份，已撤销）。
9. 构建 = `src/` + `overlay/m8/` 合成：`sh scripts/build.sh [输出目录]`。**不依赖 git 历史**（上游只发剥了 `.git` 的源码包）。
10. 上游原件双存：`upstream/<rNN>/` 目录 + `upstream-r<NN>` tag。
11. 每次改动的本地快照：`saves/<日期>-<主题>/`（改动文件原文 + diff + 说明）；上游冷备：`saves/upstream-archive/*.bundle`。

## 三、内核线

12. 只开发当前主线内核：M8 = `6.18.54-m8-probe12`。旧线冻结，冻结后不再改。
13. 兼容性只针对当前内核线，跨内核不承诺。
14. 本项目不设冻结线归档目录（`archive/<线>-pkg/` 不适用）。

## 四、文档与发版说明

15. 主页沿用 M8 现有骨架，不按其它机型重排；与其它机型的差异不单独成文，只写 M8 内部的取舍。
16. **每次 Release 正文固定四段**：
    - 做了什么
    - 改了什么
    - 未修复问题
    - 本版未包含的功能
17. 未实机验收的功能必须明写「代码已改，未实机验收」，禁止写成「已支持 / 已修复」。
18. 云端通话不可用时，任何版本文档与 Release 正文必须在开头红字标注，不得因为「媒体能建链」而暗示可用。
19. 网页类改动的验收要写清：点了哪个按钮 → 返回什么文案 → 截图路径。不接受只写「页面正常」。

## 五、版本号

20. 格式：`airsim-<机型>-0.1.0.<N>-r<NN>-m8`（全小写，tag 前加 `v`）。
21. `0.1.0` 与上游一致；`r<NN>` 对齐上游 release；`<N>` 每出一包 +1，只给在研线加。
22. **版本只写 `overlay/m8/VERSION` 一处真源**，其余位置（`m8-pkg/VERSION`、打包暂存 `VERSION`、二进制编译参数 `-X main.version=`、装机清单）一律由脚本写入，禁止手改。
23. `scripts/bump-version.sh` 从当前 `VERSION` 读取 `r<NN>`（不写死），遇到非在研内核线直接拒绝。

## 六、构建与产物

24. Go 二进制在本机交叉编，工具在 `~/Documents/doubaokaifagongju`；项目脚本留本项目内，不共享不参数化。
25. 内核模块 `.ko` 必须在 Linux + aarch64 交叉环境编，kit 归档进 `kbuild/`（不入库）。
26. 每个产物记录 **sha256 + 字节数**（md5 不再使用），写进版本说明。
27. 产物文件名只允许 `[a-z0-9.-]`：**禁止括号、空格、中文**（GitHub 会把括号改成点并导致上传失败）。
28. 打包卫生：`COPYFILE_DISABLE=1` 必带（否则 macOS 的 `._*` 进包）；暂存方向是「源码 → 暂存」，反了会打包空气。
29. **「验过的」必须等于「发出去的」**：打包后核对 rpcd 脚本、LuCI 页面、两个二进制的 sha256 与设备一致，不一致不许发。

## 七、设备操作与安全

30. 设备重启由用户亲手按，任何情况下不代劳。
31. 设备能力事实：无 `base64`（用 `openssl base64 -A`）、无 `reboot` 权限（只能删 `/tmp/lib/airsim` + `/etc/init.d/airsim-m8 restart`）、无 `stty/nohup/pkill/file/lsblk/diff`。
32. `rpcd` 重启会失效 LuCI 登录态：改完必须重新登录再验收。
33. 二进制不能热覆盖（`Text file busy`）：必须 `stop → 替换 → start`。
34. 备份/恢复的安全边界：路径白名单必须放行 tar 的 `./` 与 `./config/` 目录条目；指纹不符即拒绝并回显双侧短 id；恢复前自动快照 `/tmp/airsim-before-restore-*`；包体超过 8 MB 拒收。

## 八、真机验收判据

35. 内核/音频类：模块加载数、内存缺失页、声卡节点、PCM 通路、`dmesg` 返回值。
36. 通话类：另记下行 / 上行 / 丢帧三个数。
37. 网页类：按钮 → 文案 → 截图，三件齐全才算过。
