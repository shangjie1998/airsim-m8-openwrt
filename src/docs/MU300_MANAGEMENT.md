## 使用入口

LuCI → 服务 → AirSIM → **管理与维护**。原 AirSIM 地址转到“设备概览”，已有服务、配对、拨号与短信操作保留。

### 管理设置

- **仅局域网**：保留认证的 VoWLAN 控制/PCM 和 Bonjour；Agent 禁用 Relay 注册、心跳、云端事件和命令拉取。不会删除原云端配对资料。
- **云端 + 局域网**：允许现有有效云端配对工作，仍保留局域网。不会把客户端的纯本地配对自动提升为云端授权。
- **Relay HTTPS 地址**：留空跟随客户端配对地址；填写后作为允许的目标地址，必须与配对中的地址匹配。更换地址不会重写旧凭据的投递目的地，旧地址不匹配时云端被阻止。需在客户端设置相同 Relay 并重新配对；本插件不能部署 Relay 或配置 APNs 提供方密钥。
- **可信 LAN 接口**：只绑定该接口的私有 IPv4，不更改网络接口、默认路由或防火墙。不支持任意公网绑定；原 LAN 信任与媒体传输边界保持不变。
- **三个外部端口**：配对、认证控制、认证 PCM；1024–65535、互不重复，不能占用内部 7580/7581/8575/8576。默认 8580/8581/8582。Bonjour 广播与监听使用同一份设置；已保存的客户端连接需要重新发现，必要时重新配对。

更改流程：结束通话 → 在概览关闭服务 → 保存设置 → 在概览手动启动 → 检查实际运行状态。**保存不会自动启动或重启**。运行中的两个进程持有共享文件锁，保存需独占锁；旧版本另有 procd 和内部端口探测，防止服务运行时保存。保存前检查接口和端口，后端为最终校验者。端口预检不保证启动时不会被其他服务占用，启动成功仍以实际状态为准。

管理设置原子写入设备私有数据目录 `management.json`（0600），不改写云端凭据。默认云端允许策略保持旧版行为，真正可用性仍依赖配对配置。升级/卸载不清除此文件。先保留旧版可信安装包；回退到 r12 会忽略此新文件，不能认为旧版本仍执行 r13 的局域网限制。

### Relay 状态

区分服务未就绪、局域网限制、Relay 变更需配对、配对未启用云端、最近请求错误、已配置未确认连接，以及命令通道已连接。连接状态来自 Agent；不靠“填了 URL”显示在线，也不把命令通道当作真实双向通话验收。

### 维护工具

- **导出脱敏诊断**：下载 JSON 状态白名单。仅保留插件版本、采集时间、连接模式和布尔状态；不导出号码、短信、IP/URL、身份、配对码、密钥、原始错误文本或音频，不自动上传。服务关闭时报告明确标注状态不可用，不冒充空闲。
- **版本说明**：页面本地内置，无需联网，实际安装版本由二进制版本返回。
- **插件更新（r14）**：定期检查固定 GitHub 仓库，可关闭自动检查、选择预览频道或手动刷新。用户关闭电话服务后可点击并确认升级；后台校验哈希、签名、架构、必要依赖与空闲状态，显示安装进度与最终结果。不会自动安装或降级。详细边界见 [插件更新说明](PLUGIN_UPDATES.md)。

当前源码已取消安装/更新的系统与内核版本白名单；具体范围和旧 Release 的区别见 [安装兼容性说明](INSTALL_COMPATIBILITY.md)。

## 实现与测试

- `cmd/airsim-mu300d/management.go`：认证 rpcd 背后的短生命周期管理 CLI，无新增网络端口；设置、运行锁、Agent 包装启动器、白名单报告、固定地址更新检查。
- `patches/AirSIM-mu300.patch`：仅 MU300 profile 的云端限制策略，以及命令连接状态；不重定向已有凭据。
- `packaging/openwrt/root/.../airsim/manage.js`：设置与维护页面。轮询不修改表单草稿；状态未知时不能保存；设置保存和检查更新使用写 ACL。
- 版本说明和安装器分离：`scripts/install.sh` 固定下载同版 r15，包版本与签名校验保持一致。
