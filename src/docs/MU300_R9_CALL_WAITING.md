## 已定位问题

实机原有 index=1 active 通话；index=2 waiting 来电的两次接听均返回 502。
客户端提交的 ID 与 Agent 发布的 waiting ID 一致。旧控制器要求 CLCC 恰好一路，
且旧单记录模型切换 index 时重建 UUID，切回 index=1 又产生第三个身份。

## r9 行为

- 每个存续 CLCC index 对应独立 UUID。消失、方向变化、非空号码变化、已接通后重新进入建立阶段时退休旧 ID。
- 同一通话 active/held 切换、响应重排、另一来电加入或离开，不改变已有 UUID。
- 所有结束的通话进入 history；active 保留旧客户端协议，calls 数组用于完整诊断。
- 一路 active + 一路 waiting：CHLD=2 保持原通话并接听等待来电，不自动终止原通话。
- 唯一等待来电 + 一路 active 的拒接：CHLD=0；多路中的已接通通话挂断：CHLD=1x。
- 先查询 CHLD 能力，再刷新 CLCC 核对同一 UUID 和所有同场通话的身份/状态。
- 不明组合、不支持能力、过期 ID、缺失 ID 的多路请求不执行，不回退到全局 CHUP。
- 控制命令只发一次，轮询确认目标接通/结束。未确认的 CHLD=2 在后续请求中也不重复发送。
- 普通单路保留 ATA/CHUP。DTMF 仅发送到唯一处于 active 的目标。
- 云端控制同样绑定 call_id，防止旧路径绕过定向挂断保护；完整云端多路媒体不在本次验收范围。

实机只读能力查询返回 `+CHLD:(0-4,6,7,8,11-17,21-27,71-77)`。
能力声明不等于运营商/固件实际操作已通过验证。
语义参考 [ETSI TS 127 007 §7.13/§7.22](https://www.etsi.org/deliver/etsi_ts/127000_127099/127007/17.08.00_60/ts_127007v170800p.pdf)。

## 自动化回归

Agent 全套 race 测试和 vet；插件全套 race 测试和 vet。专门覆盖：
稳定 ID、两路历史、slot 重用、遗漏 idle 的替换、响应重排、能力列表/区间解析、
等待接听和重复接听、仅挂断目标、拒接不影响原通话、能力查询期间来电结束/同场通话替换、
三路拒绝、无 ID/过期 ID、AT 超时但状态已成功、OK 但状态未变化、重试保护、
畸形/重复 CLCC 不重置身份、云端过期 ID 不能越权控制当前通话。

## 人工实机步骤（未通过前不宣称完成）

1. 服务空闲时安装 r9，验证版本、签名 health 和原配对保留。
2. 先保持一路已接通电话，再由另一部手机打入 MU300。
3. 在 iPhone AirSIM 点接听：新来电应 active，原通话应 held，两者 ID 不变；验证新来电双向声音。
4. 挂断新通话：只移除目标 ID，原通话仍保留；不要把“held”当成已挂断。
5. 另测拒接等待来电：原 active 不变；过期 ID 不影响存续通话。
6. 单路拨号、接听、挂断回归；检查 boot ID、音频错误与服务状态。
