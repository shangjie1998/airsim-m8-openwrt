# U30 Air 再次配对被拒绝：设备端修复

2026-11-03，R20 配对修复。只修改独立 U30 Air 集成和固定 Agent 的隔离补丁；AirSIM iOS/Android 及上游工作树不变。

## 现象与原因

用户反馈：输入正确验证码仍提示配对拒绝，切换 iPhone AirSIM 到本地模式后可以配对。

当前客户端的非本地配对请求携带 `live_activity_presentation: "agent_status"`，本地模式在写入该字段之前结束编码。R19 固定的 Agent `pushRegistration` 不包含此字段，严格 JSON 解码返回 HTTP 400。设备已有日志也记录了注册 400 后成功 200 的过程；旧实现自动化测试复现了 `unknown field "live_activity_presentation"`。这并不表示所有配对拒绝都是同一原因，错误验证码、过期会话仍须拒绝。

另外，网关曾直接把 Agent 推送状态中的 `configured` 转给配对客户端。该字段受云功能开关、Relay 地址及设备管理策略影响，即使注册已经成功保存，也可能是 false；客户端会将其解释为配对失败。

原流程在 Agent 接受注册之前写入局域网密钥，失败重试可能消耗客户端名额。

## 修复

- Agent 隔离补丁明确接收并持久化 `live_activity_presentation`，继续转发到 Relay，保留客户端要求的设备状态展示语义。仍严格拒绝未识别字段。
- 只有 Agent 返回成功且状态响应格式有效、网关密钥保存成功后，配对接口才返回 `configured: true`。原推送就绪状态改以 `push_configured` 返回，原云开关、管理限制及推送能力字段保持原样。Agent 的状态接口含义不变。
- 提交前只检查网关密钥和容量，Agent 接受注册后才写入新密钥，拒绝或异常响应不再新增网关客户端。
- 保留已有密钥和 16 个客户端上限，不擅自删除历史配对。容量检查在实际保存时再次执行；网关写盘失败仍返回失败，不能宣称两个独立状态文件具备跨文件原子事务。

## 验证与边界

自动化覆盖：真实加密请求的首次/再次配对、云推送未就绪、管理策略限制、错误验证码、成功请求重放、无效 Agent 响应、非法密钥与容量已满，以及新增字段经过 Agent 严格解码、持久化、重载后转发到本地 TLS Relay 测试端点。

候选构建标记：`0.1.0-r19-pairing.1`。2026-11-03 经用户授权，已备份并安装到 USB 连接的 U30 Air，只重启 AirSIM 服务，未重启设备。安装前确认通话、媒体及短信任务空闲；安装后两项服务运行，Agent 可达，版本及程序摘要匹配，已有设备身份、配对密钥和服务配置保持原样。配对窗口未开启时，信息接口返回预期的 HTTP 410。

2026-11-03 用户确认：iPhone AirSIM 保持云模式，分别获取新验证码连续配对两次，两次均成功，不再提示验证码错误。云模式重复配对验收通过。

公网推送能力未因本次配对测试完成整体验收；本修复纳入 R20 开发预览；R20 完整 APK 的安装回归与候选二进制的配对验收分别记录。
