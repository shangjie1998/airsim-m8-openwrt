# 插件更新与管理功能（R16）

> [!WARNING]
> **安装前必须按系统版本选包：R16 仅适用于 1031 之后的新系统版本；R12 仅适用于 1031 之前的旧系统版本。不得跨版本线混装，也不要仅因 R16 更新就升级旧系统。**
> 这里的 1031 指 mu300-linux 系统版本线，不是插件下载或安装日期。无法确认所属版本线时，先核对系统发布说明再安装；音频模块还必须通过内核、配置与 ABI 检查。

本功能只管理 `kai-wu-cortex/airsim-mu300` 插件，不升级 OpenWrt、内核、
mu300-audio 或 AirSIM iOS/Android。r13 的管理设置、Relay 状态、端口设置、
脱敏诊断和版本说明全部保留，r14 新增自动检查和用户确认安装。

## 使用

打开 **LuCI → 服务 → AirSIM → 管理与维护**。

1. 默认每 6 小时检查一次 GitHub Release，可关闭自动检查，也可切换是否包含开发预览。
   只有公开版本请求，不上传设备身份、配对信息、号码、短信或诊断。
2. “检查更新”立即刷新；后台结果缓存，页面轮询只读取缓存，不反复访问 GitHub。
3. 发现新版本后，必须先核对系统版本线：1031 之前系统保持 R12，不升级 R16；1031 之后系统才使用 R16。确认适用后，在概览页关闭电话服务，再选择“下载并更新”并确认目标版本。
4. 页面显示下载、验证、安装、成功或失败；安装期间可以刷新页面查看同一任务。
5. 成功后刷新 LuCI，再到概览启动电话服务。不会自动重拨、接听、发短信或开启配对。

当前为开发预览，默认包含预览版。工作区版本比公开 Release 新时显示“领先”，
不会自动降级。不存在新 Release 时不能以“升级成功”冒充真实在线升级验收。

## 安装边界

- 固定项目、固定格式的版本号、固定资产名；不接受任意 URL、包名或 shell 命令。
- 仅允许比当前二进制更新的版本，执行时重新核对频道中的最新 Release。
- 下载限制大小与时间，仅允许 GitHub 官方 HTTPS 下载域跳转。
- 校验 SHA256SUMS、内置签名公钥指纹，再通过 APK 签名校验。
  从已签名元数据核对包名、目标版本和架构；不使用 `--allow-untrusted`。
- 两次检查服务、原始 CLCC 和短信任务状态。安装阶段持有独占管理锁，
  服务启动器和设置保存无法同时进入；未知状态拒绝安装。
- 当前源码取消 mu300-linux / OpenWrt / 内核精确版本白名单。
  更新仍要求 aarch64，以及 apk、mu300-at、mu300-voice、mu300-audio-dsp 工具可执行。
  不自动安装旧音频驱动，不绕过音频上游 ABI 检查；其他硬件仍须完成适配。
  该实现由 R16 保留，r15 已撤回；取消程序硬拦截不改变系统版本选型要求，见 [安装兼容性说明](INSTALL_COMPATIBILITY.md)。
- 安装使用已验证的本地 APK，禁止包管理器联网拉取其他依赖。
- 升级后再次执行新二进制读取实际版本；只在匹配时报告成功。
  失败或断电后标记失败/中断，不自动重试、不自动回退、不声称旧版本必然完整。
  需要恢复时，使用先前可信安装包或设备备份，保留配对与配置。

## 实现

`airsim-update` 是独立 procd 服务，电话服务关闭时仍能检查公开版本。
它每分钟检查缓存是否到期，实际网络请求间隔 6 小时；改变频道后会重新检查。
关闭自动检查后仍允许手动检查。

私有数据目录增加 `update-policy.json`、`update-cache.json`、`update-job.json`
与锁文件，权限 0600。任务通过独占锁防重复，后台安装进程运行自己的临时副本，
不会因插件二进制被替换而丢失执行程序；安装结果跨页面保留。
升级时不要删除这些文件或原有配对文件。

rpcd 读取权限只允许缓存状态；偏好保存、联网检查及安装都需要写权限。
不增加网络监听端口，不执行从 Release 下载的脚本。

设备如已存在定制的硬件启动脚本，可由管理员保存在
`/etc/airsim/prepare.local`（root 所有，0600）。标准 prepare 会执行该文件，
插件包不提供、修改或删除它。它用于保留既有适配，不会自动启用驱动版本绕过。
本机音频兼容性仍独立验证；不能借此声明上游音频版本受支持。

## 验证

自动化覆盖：空闲判断、未知状态拒绝、错误 URL/跳转、重复/错误校验和、
签名拒绝后的禁止安装、已签名包身份不匹配、安装失败、安装后版本不匹配、
任务中断、缓存、偏好持久化、ACL、确认/取消/重复点击和服务运行时禁用升级。
实际 GitHub 下载并安装“未来新版本”的完整链路须在有可用的新 Release 时验收；
不能为了测试而降级用户设备。
