# AirSIM 短信接入（R19 开发预览）

R17 已发布版本只有 LuCI 短信入口。R18 候选开发、R19 发布的适配把 MU300 原生短信库接到 AirSIM 现有协议，不需要修改或重新签名 iPhone 客户端。此前 R18 候选已安装进行通话验证，但尚未发送真实短信；本轮 R19 未安装实机；不能视为短信收发已经验收。

## 使用范围

- 前台同网连接并完成配对的 AirSIM，可获取收件箱、接收短信变化事件、确认本地保存并提交发送。
- 继续复用 R17 的 U30 Air 一体音频环境；不扩大 F50 或其他内核支持。
- 发送仅单条、最多 70 字，不支持 emoji、长短信自动拆分及多 SIM 选择。拒绝控制字符与无效号码。
- 首次连接会同步设备原生短信库中已有的收件短信；发件短信由客户端在成功回执后保存。
- 已有 Relay 注册可复用 Agent 的新短信事件和发送命令，但后台 APNs、云端收发、锁屏到达与实际客户端版本兼容性均未实机验收。本修改不部署 Relay，也不新增推送凭据。

## 数据与发送语义

设备的 `mu300-smsd` 继续负责接收、PDU 解码及 SIM 存储管理。Agent 每三秒只读扫描原生 `/etc/mu300/sms-pool/msg`，不调用会标记已读的 `show`，不切换 AT 短信编码，不抢占串口。

短信使用稳定 `delivery_id`。手机确认本地保存后，Agent 把已交付标识原子写入自身私有目录；重启后仍去重。确认不会删除或改写设备原短信。每批最多 256 条，确认后继续交付剩余短信。原生短信库格式异常或交付状态损坏时报告错误，不清空数据。

发送使用系统 `/opt/mu300/bin/mu300-sms send --stdin`，号码和正文通过标准输入传递，不拼接 shell 命令。提交前确认通话空闲；只在原生工具给出明确的发送回执后返回成功。这里的成功表示基带接受提交，不是收件人已阅读或已收到的运营商送达报告。

并发提交被拒绝。同一号码和内容在两分钟内重复请求，复用已经确认的结果；结果未知时，两分钟内拒绝进一步提交，提示用户先核对收件端。服务重启后仍保留该保护，不自动重发。发送记录只保存内容摘要和结果，不额外保存号码或正文。

## 协议与验证

沿用客户端已有接口：`GET /api/sms`、`GET /api/sms/status`、`POST /api/sms/send`、`POST /api/sms/refresh`、`POST /api/sms/ack`、`PATCH /api/sms/settings`。网关继续验证 HMAC、时间戳和 nonce，拒绝篡改、重放及超大请求。`clear-module` 和任意 AT/删除入口不对外开放；清理设置明确返回关闭。

已通过插件 Go race/vet、固定基线重新应用补丁后的 Agent race/vet、29 项 Node 测试、14 项一体安装流程测试和 4 项固件缓存恢复测试。新增 10 个 Agent 短信测试及网关/升级保护测试，覆盖原生短信格式、正文和时间映射、发件过滤、重启去重、索引复用、持久化失败、分批交付、并发刷新/确认、输入限制、重复/并发提交、未知结果、客户端 HTTP 字段以及网关鉴权。

实机验收需要：安装候选后由用户在 AirSIM 查看收件箱；从自己的测试手机向 U30 Air 发一条测试短信，确认自动出现；在 AirSIM 回复一条指定的测试短信并确认对端收到。真实号码和正文不写入仓库或测试日志；真实收发须另外限定测试范围，不能从构建候选包推断授权。

## 安装与回退

包名为 `luci-app-airsim-0.1.0-r19.apk`，沿用项目签名和 R17 音频模块。从 [R19 Release](https://github.com/kai-wu-cortex/airsim-mu300/releases/tag/v0.1.0-r19) 获取同版包、公钥和校验清单。安装须先确认电话、媒体和短信任务空闲，备份 R17 插件和 Agent；不更改系统、内核、音频扩展或配对数据。

回退到可信的 R17 包恢复旧协议范围。原生短信库始终保留；自身私有 `mu300-sms` 目录中的交付确认和提交摘要也应保留，避免再次升级时回流或重复发送。
